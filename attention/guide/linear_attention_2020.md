# Rethinking Attention with Performers
https://arxiv.org/abs/2009.14794

下面用尽量通俗的方式，把这篇论文里 Performer 的关键原理给你捋清楚：**它想解决什么问题、用了什么数学“魔法”、这些魔法直观上在干嘛**。

---

## 一、Performer 想解决什么问题？

先看普通 Transformer 的自注意力：

- 对长度为 \(L\) 的序列，注意力要算一个 \(L \times L\) 的矩阵  
- 时间复杂度：**O(\(L^2 d\))**（\(d\) 是隐藏维度）  
- 显存复杂度：**O(\(L^2\))**

也就是说：

- 句子 1000 个 token，要算 100 万对关系  
- 句子 10000 个 token，要算 1 亿对关系  

在**长文本、蛋白质序列、基因序列**这类超长序列上几乎没法用。

**Performer 的目标：**

> 把原来 **二次复杂度的注意力** 变成 **线性复杂度**，同时尽量保持和标准 softmax 注意力接近，而且有理论保证。

---

## 二、核心招式：把 softmax 注意力“核函数化”再近似

标准自注意力的核心是这一块：

\[
\text{Att}(Q, K, V) = \text{softmax}\Big(\frac{QK^\top}{\sqrt{d}}\Big) V
\]

其中 softmax 里本质是在用 **核函数**

\[
\text{SM}(q, k) = \exp\Big(\frac{q^\top k}{\sqrt{d}}\Big)
\]

所以可以把注意力看成：

> “用 softmax kernel \(\exp(q^\top k)\) 衡量 query 和 key 的相似度，然后加权求和 V”

Performer 的关键思路：

1. **把 softmax 当成一个核函数（kernel）**  
2. **用随机特征（random features）来近似这个核函数**  
3. 把原来需要显式算 \(QK^\top\) 的二次操作，变成线性链式计算

### 核函数 → 随机特征的经典公式

如果有一个核函数 \(K(x, y)\)，可以找到一个随机映射 \(\phi(x)\)，满足：

\[
K(x, y) = \mathbb{E}\big[ \phi(x)^\top \phi(y) \big]
\]

那我们就可以用**采样平均**来近似：

\[
K(x, y) \approx \phi(x)^\top \phi(y)
\]

Performer 做的事就是：

- 把 softmax 核 \(\exp(q^\top k)\) 写成一个这种期望形式
- 设计一个合适的随机映射 \(\phi\)，让：
  \[
  \exp(q^\top k) \approx \phi(q)^\top \phi(k)
  \]
- 然后在注意力里，**用 \(\phi(Q)\phi(K)^\top\) 替代 \(\exp(QK^\top)\)**，把复杂度降下来

## 三、FAVOR+：如何把 O(\(L^2\)) 变成 O(\(L\))？

### 1. 标准注意力的写法

标准注意力可以写成：

\[
A = \text{softmax}(QK^\top) \quad (\text{这是 } L \times L \text{ 矩阵})
\]
\[
\text{Att}(Q, K, V) = A V
\]

如果直接算 \(QK^\top\)，就是 O(\(L^2d\))。

### 2. 使用核近似后的新写法

Performer 做了两步：

1. 用随机特征 \(\phi\) 近似 softmax 核：

   \[
   \exp(q^\top k) \approx \phi(q)^\top \phi(k)
   \]

2. 把注意力写成线性形式：

   - 令 \(Q' = \phi(Q) \in \mathbb{R}^{L \times r}\)  
   - \(K' = \phi(K) \in \mathbb{R}^{L \times r}\)，\(r\) 是随机特征维度（如 256）

   近似的注意力可以写成：

   \[
   \hat{A}V \approx D^{-1} Q' (K'^\top V)
   \]

   同时归一化项的分母也可以类似写成：

   \[
   D \approx \text{diag}\big(Q' (K'^\top \mathbf{1})\big)
   \]

   这里每一步都是**矩阵乘矩阵或矩阵乘向量**，但不再有显式的 \(L \times L\) 矩阵。

**复杂度分析：**

- 计算 \(K'^\top V\)：O(\(L r d\))  
- 计算 \(Q'(K'^\top V)\)：O(\(L r d\))  
- 整体复杂度：**O(\(L r d\))，线性于 L**

只要 \(r \ll L\)（通常 64、128、256），就远小于 O(\(L^2 d\))。

这套线性注意力机制就是他们叫的 **FAVOR+（Fast Attention Via positive Orthogonal Random features）**。

## 四、两个关键技术：PRF 和 ORF 在干嘛？

要想让上面的核近似好用，不光要“能近似”，还要：

- 数值稳定（不能一会儿爆、一会儿全是 0）
- 方差小（同样维度 r 下近似要足够准）

Performer 提出两个关键的随机特征设计：

### 1. PRF：Positive Random Features（正向随机特征）

目标：**让 \(\phi(x)\) 的每个分量都是非负的**。

为什么很重要？

- 注意力的 softmax 本质上给的是**非负权重**，如果近似的核值可以为负，就会导致权重乱七八糟甚至抵消
- 非负特征能保证近似得到的注意力权重**更稳定、更接近 softmax**，尤其在深层网络里

他们给出了一个形式（直观理解，不必死记）：

\[
\phi(x) = \text{常数} \cdot \exp\Big( \omega^\top x - \frac{\|x\|^2}{2} \Big)
\]

再配上一些 trig（正余弦）或变体，保证：

\[
\mathbb{E}_\omega[\phi(x)^\top \phi(y)] = \exp(x^\top y)
\]

直觉比公式重要：

> PRF 就是用“**纯正的、不会为负的随机标签**”来近似 softmax 相似度，让注意力层不会因为负数乱掉。

### 2. ORF：Orthogonal Random Features（正交随机特征）

目标：**降低估计方差 → 用更少的特征就能近似得更好**。

普通做法：随机采很多 \(\omega\)，彼此之间没关系  
问题：样本之间相关性不受控制，方差可能很大，需要很多样本（大 r）才准。

ORF 的做法：

- 把这些 \(\omega\) 做成**相互正交**（或近似正交）  
- 像在高维空间里选一组“彼此垂直的方向”

收益：

- 理论上可以证明：在同样 r 的情况下，ORF 比普通随机特征有**更低的 MSE（均方误差）**和更好的尾部界  
- 实际上，r=256 这种规模就能有相当不错的近似效果，不需要上千维

**PRF + ORF 组合 = FAVOR+**  
既保证非负、稳定，又保证方差小、收敛快。

## 五、从直观角度再解释一次：它到底在“偷懒”什么？

想象你要：

> “给每个词分配一个权重，看它对当前这个词有多重要，然后加权求和。”

### 原来的算法（标准 Transformer）

- 对当前词，**和所有词逐个比对**（点积 → exp → softmax）  
- 就像：你要评价 1000 个人和你各自的“相似度”，一一对比

### Performer 的算法

1. 给每一个词，先分配一个随机生成的、但设计过的“标签向量” \(\phi(x)\)
2. 这些标签有个特性：  
   - 两个词越相似，**标签向量的点积期望越大**  
   - 这点积就近似 softmax 那个 \(\exp(q^\top k)\)
3. 于是你可以：
   - 先把所有 key 的标签和 value 做一个“总结”  
   - 再用 query 的标签去“查询这个总结”

所以：

- 原来是：**对每个 query，重新和所有 key 比一遍**  
- 现在是：**先做一个关于 key, value 的“压缩表”，然后对每个 query 只查这张表**

这就是复杂度从 O(\(L^2\)) → O(\(L\)) 的本质原因。

## 六、单向 / 双向注意力 & 前缀和技巧

Performer 不仅能做普通的“全局（双向）自注意力”，也能做“单向（因果）注意力”（像 GPT 那样：只能看左边）。

- 双向注意力：  
  按上面说的那样直接算就行：  
  \[
  Q' (K'^\top V)
  \]
- 单向注意力：  
  需要保证每个位置 i **只能用到 1…i 的信息**。  
  Performer 用了**前缀和（prefix-sum）技巧**：
  - 对 \(K'\) 和 \(V\) 做扫描式累积，位置 i 的结果只用到前面 i 个 token 的信息
  - 仍然能保持 O(\(L\)) 的整体复杂度

直观理解：

> 单向注意力里，他们等价地把“只看左边”这件事，转换成了在随机特征空间里对前缀的累积和查询。

---

## 七、理论保证：不只是“玄学近似”

论文还给了一堆理论结论，大意如下（只讲含义，不推公式）：

1. **无偏性**：  
   平均意义下，FAVOR+ 近似得到的注意力矩阵 \(\hat{A}\) 的期望等于真实的 softmax 注意力 \(A\)，或者非常接近。

2. **统一收敛性**：  
   在一定条件下，只要随机特征数量 \(m\) 足够大（但仍远小于 L），可以保证对**所有** query-key 对，\(\hat{A}\) 和 \(A\) 的差异都被一个小的上界控制住。

3. **方差 / 尾部界**：  
   使用 ORF 后，近似误差的方差更小，并且“出大差错”的概率有严格的指数级衰减界。

直观解读：

> 不是“乱投影，希望结果还行”，而是有数学保证：随着随机特征数增加，近似会稳稳地逼近真实注意力。

---

## 八、总结：Performer 的关键原理一句话版

- **把 softmax 注意力看成核函数**
- **用“非负 + 正交”的随机特征（FAVOR+）近似这个核**
- 把原本要显式算 \(L \times L\) 的注意力矩阵，重写成若干个 **线性复杂度的矩阵乘法**
- 理论上：无偏、收敛、有误差界；实践上：能在长序列任务上撑得住，还保持接近 Transformer 的性能
